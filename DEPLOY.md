# Деплой BankFlow

Документацию BotHost из среды разработки открыть не удалось. Шаги ниже общие:
названия полей в панели BotHost могут отличаться.

## Перед деплоем
1. **Бэкап базы.** При старте `create_tables()` добавит новые таблицы и столбцы
   (`balance_history`, согласия в `users`, даты и `offer_id` в заявках). Существующие данные не меняются,
   но бэкап обязателен:
   ```
   pg_dump "$DATABASE_URL" > bankflow_backup_$(date +%F).sql
   ```
2. **Остановить старого бота.** Два процесса с одним токеном в режиме polling мешают друг другу
   (ошибка `Conflict: terminated by other getUpdates request`).

## Запуск
- Python 3.12+ (проверено на 3.13), зависимости: `pip install -r requirements.txt`
- Команда запуска: `python main.py`
- Либо Docker: в репозитории есть `Dockerfile`.
- Режим: long polling, входящий webhook не нужен.

## Переменные окружения
| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | новый токен из @BotFather |
| `DATABASE_URL` | да | `postgresql://user:password@host:5432/dbname` |
| `ADMIN_ID` | да | Telegram ID админа (число) |
| `SUPPORT_USERNAME` | да | ник поддержки без `@` |
| `PORT` | нет | порт HTTP-сервера (health, Mini App), по умолчанию 10000 |
| `WEBAPP_URL` | нет | HTTPS-адрес Mini App, например `https://<домен>/app/` |

## Mini App
Работает, только если хостинг даёт публичный **HTTPS**-адрес для порта `PORT`.
- Есть адрес: задать `WEBAPP_URL=https://<адрес>/app/`, перезапустить. В меню бота появится «📱 Открыть приложение».
- Нет адреса: бот работает без Mini App, `WEBAPP_URL` оставить пустым.

## Проверка после запуска
1. В логах: `BankFlow запущен ✅ Порт: ...`
2. `https://<адрес>/` отвечает `BankFlow is running` (если хостинг даёт адрес).
3. В боте: `/start` → экран 18+ → согласие → меню.
4. Тестовый сценарий: оффер → «Получить ссылку» → админ «Выдать ссылку» → «Я выполнил условия» →
   админ получил заявку → «Подтвердить» → баланс вырос → вывод → «Выплачено».
5. Перезапустить сервис и убедиться, что бот снова отвечает.
