## Что такое BankFlow
- Telegram-бот (и будущий Mini App) — витрина банковских предложений с вознаграждением. Владелец — ИП, официальный вебмастер партнёрских сетей (со слов владельца основные — «Airco Group», Pompadour и «Бизнес-система»; в ссылках встречаются домены fincpanetwork.ru, trk.ppdu.ru, lk.bs-rko.ru, rko-group.ru, alfa.me — уточни у владельца точные названия сетей). Офферы согласованы с сетями, кэшбэк клиенту разрешён (со слов владельца). Доход владелец отражает как ИП, реклама маркируется (erid в ссылках).
- Как это работает для клиента: выбирает оффер → читает условия → оформляет продукт по ссылке (прямой или персональной) → выполняет условие банка (покупка, активация) → нажимает «Выполнил» → заявка на проверку → админ подтверждает или отклоняет → вознаграждение на баланс в боте → клиент запрашивает вывод (номер телефона + банк, СБП) → админ выплачивает и отмечает «выплачено».
- Категории: дебетовые карты, кредитные карты, МФО (начинаем с займов без процентов), для бизнеса (РКО), инвестиции (пока пусто).
- Пример экономики: сеть платит владельцу, допустим, 4000 ₽, клиенту уходит часть, например 1500 ₽ (поле `reward` в оффере — это сумма для клиента).

## Стек и файлы
- Python, aiogram 3, PostgreSQL через `psycopg2` (синхронно), aiohttp (health-сервер для хостинга), python-dotenv. Версии в `requirements.txt` не закреплены — закрепи.
- `main.py` — точка входа: `Dispatcher`, подключение роутеров, health-сервер aiohttp, polling.
- `config.py` — переменные окружения (`BOT_TOKEN`, `DATABASE_URL`, `ADMIN_ID`, `SUPPORT_USERNAME`, `PORT`), понятная ошибка при отсутствии. Шаблон — `.env.example`.
- `loader.py` — объект `bot`. `states.py` — все FSM-состояния.
- `privacy.py` — политика конфиденциальности и текст согласия (`PRIVACY_VERSION`: при смене текста пользователи подтверждают заново). `middlewares.py` — `OnboardingMiddleware`: пока нет 18+ и согласия на ПД, пускает только `/start`, `/privacy` и кнопки входа (админ проходит всегда).
- `webapp/` — Mini App: `auth.py` (проверка initData), `api.py` (JSON API `/api/*`, страница `/app/`), `static/` (index.html, app.js, style.css без сборки). Работает на том же aiohttp-сервере, что и health. `notifications.py` — уведомления админу из Mini App (те же кнопки, ввод экранируется). `progress.py` — уровни и достижения для Mini App (в handlers те же значения пока продублированы). `WEBAPP_URL` в env — кнопка «Открыть приложение» в меню бота.
- `handlers/` — роутеры aiogram, порядок подключения в `handlers/__init__.py` важен (обработчики сообщений без фильтра состояния срабатывают в любом состоянии): `onboarding` (18+, согласие, `/privacy`) → `menu` (старт, главное меню) → `admin` (админка, заявки, комментарии, `/broadcast100`) → `academy` → `business` (самозанятость/ИП/РКО, вопросы админу, звонок ВТБ) → `catalog` (категории, карточка оффера, персональные ссылки, «Выполнил») → `cabinet` (кабинет, продукты, рефералы, достижения, задания, заявки) → `legacy` (старая reply-клавиатура, кандидаты на удаление) → `withdrawals` (вывод, выплаты).
- `database.py` — все запросы к Postgres, `create_tables()`.
- `offers.py` — `MAGNIT_LINK`, словарь `OFFERS` (name, category, type, reward, min_age, max_age, access: `direct`/`personal`/`manual`, link, condition, requirements) и `CATEGORIES`.
- Таблицы: `users` (balance, points, level, total_earned, created_at), `applications`, `withdrawals`, `link_requests`, `referrals`, `referral_rewards`, `achievements`, `user_products`, `balance_history` (income/expense). В `users` также `age_confirmed_at`, `pd_consent_at`, `pd_consent_version`.

## РАЗВИТИЕ: BankFlow для других вебмастеров (после фаз 0–6, не раньше)
Идея владельца: помогать другим ребятам-вебмастерам и зарабатывать на этом, а не только на своих клиентах. Делаем по ступеням: каждая следующая — только когда предыдущая работает и приносит деньги. Пока идёт фаза 0–6, ничего из этого не кодим, но архитектуру не закрываем: таблицы и код пишем так, чтобы потом можно было добавить поле `tenant_id` (чья витрина) без переписывания.

### Ступень 1. Партнёры BankFlow (самое простое, первым)
- Любой пользователь может стать партнёром: получает свою ссылку и долю от подтверждённых заявок приведённых клиентов (один уровень, без «сетки» и пирамид).
- Кабинет партнёра в Mini App: переходы, регистрации, заявки, подтверждено, заработано, выплаты; готовые тексты и картинки для постов и сторис (с маркировкой «Реклама»).
- Основа уже есть (`referrals`, `referral_rewards`) — довести до нормальной статистики и выплат.

### Ступень 2. Витрина под ключ (white-label), платная подписка
- Вебмастер подключает своего бота (токен от @BotFather), выбирает офферы из каталога, вставляет СВОИ партнёрские ссылки (свои ID в сетях) и свои суммы кэшбэка, ставит название, логотип и цвета — и получает такой же бот + Mini App, как BankFlow.
- У каждого свой кабинет: заявки его клиентов, подтверждение, выплаты, статистика, рассылки.
- Технически: один сервер и одна база на всех, у каждой записи `tenant_id`; боты работают через webhook (aiogram умеет много ботов в одном приложении); Mini App один, оформление подтягивается по боту. Токены вебмастеров хранить зашифрованными.
- Оплата подписки: тарифы по месяцам (например, «старт» — до N офферов и пользователей, «про» — без ограничений, свой домен, постбэки). Принимать оплату как ИП через подключённый эквайринг или Telegram Stars — выбери вариант по документации, покажи владельцу.
- Пилот вручную: сначала 3–5 знакомых вебмастеров, владелец настраивает им витрины сам, собирает отзывы; автоматическое подключение — потом.

### Ступень 3. Инструменты для вебмастеров (подписка или часть тарифа)
- Общий каталог офферов с актуальными условиями и суммами; уведомление, когда оффер меняется или отключается.
- Единый приём постбэков из разных сетей и автоматическая смена статусов заявок.
- Аналитика: какие офферы реально подтверждаются, средний срок подтверждения, конверсия по каналам.

### Обязательные правила для всех витрин (нельзя отключить в настройках)
- Только 18+, согласие на обработку ПД, экран предупреждения для кредиток и МФО, правило «оформляешь только для себя, никому не передаёшь карту и коды», маркировка рекламы — у каждой витрины свой erid и рекламодатель.
- Вебмастер подтверждает, что он официальный партнёр сетей и сам отвечает за свои выплаты клиентам и налоги. Нужны пользовательское соглашение и оферта для вебмастеров (тексты готовит владелец с юристом; ты делаешь страницы и галочку согласия).
- Платформа НЕ хранит и не переводит чужие деньги: выплаты клиентам делает каждый вебмастер сам, платформа только считает и показывает. Хранение и перевод чужих денег требуют лицензий — не делаем.
- Владелец может заблокировать витрину за нарушения (жалобы, запрещённые офферы, несовершеннолетние).
