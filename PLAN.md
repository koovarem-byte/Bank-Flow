# PLAN.md — BankFlow

Источник: раздел «ПЛАН РАБОТ» в `CLAUDE.md`. Порядок: пункт → проверка запуском → `[x]` → отдельный коммит.
`git push`, изменения структуры базы и деплой — только после «ок» владельца.
Архитектурное правило: таблицы и код пишем так, чтобы позже добавить `tenant_id` без переписывания (раздел «Развитие» не кодим).

## Фаза 0. Безопасность и порядок
- [ ] Git: если репозитория нет — `git init`, ветка `main`, первый коммит без секретов; дальше работа в ветке `dev`.
- [ ] `.gitignore`, `.env.example` (без значений), `config.py` с чтением переменных окружения. Токен из кода убрать.
- [ ] Закрепить версии в `requirements.txt`.
- [ ] Проверить подключение к базе и что `create_tables()` проходит.

## Фаза 1. Бот работает корректно
- [ ] Вынести обработчики из `start()` на верхний уровень (P0.2).
- [ ] Таблица `balance_history` (P0.3), проверить подтверждение заявки и ручное изменение баланса.
- [ ] Убрать дубли обработчиков и функций (P1.7–P1.9), `ADMIN_ID` в env (P1.10).
- [ ] Разбить `main.py` на модули по разделам (handlers/offers, cabinet, admin, business, withdrawals, academy) — без изменения поведения, проверка после каждого шага.

## Фаза 2. Законность и доверие
- [ ] 18+ при старте, офферы min_age ≥ 18 (P0.4).
- [ ] Согласие на обработку ПД и `/privacy` (P0.5).
- [ ] Маркировка «Реклама» + рекламодатель + erid в карточке оффера; экран предупреждения для кредиток и МФО; правило «только для себя» (P0.6).

## Фаза 3. Учёт лидов
- [ ] subid в ссылках по документации каждой сети (P2.12), отображение в админке.
- [ ] Эндпоинт для постбэков (за флагом, включается после настройки в сети).

## Фаза 4. Mini App
- [ ] Отдельный фронтенд + API на aiohttp с проверкой `initData` от Telegram.
- [ ] Экраны: главная, каталог по категориям с фильтрами, карточка оффера, мои заявки, вывод, рефералы, достижения.
- [ ] Стиль: чистый «финтех» (тёмная тема, один акцент, крупные цифры, понятные статусы).

## Фаза 5. Хостинг BotHost
- [ ] Выяснить по документации BotHost запуск (polling/webhook, env, HTTPS-домен для Mini App).
- [ ] Деплой, проверка `/health`, бот отвечает после перезапуска.

## Фаза 6. Тест и запуск
- [ ] Ручной сценарий: регистрация → оффер → «Выполнил» → подтверждение → баланс → вывод → «выплачено».
- [ ] Первые 20–30 пользователей, сбор ошибок, правки.

## Открытые вопросы к владельцу
